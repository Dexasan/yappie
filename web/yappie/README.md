# Yappie website and email handoff

The public site is hosted by the `yappie-public` Cloudflare Worker at
[yappie.site](https://yappie.site). Source assets are copies of the approved
Yappie artwork. The home page is the entry point for browser chat. Add the
Android install link to `public/index.html` when the app is publicly released.
The privacy and support pages are for the Android beta; a formal privacy contact
is still needed before a public store launch.

From the repository root, with Wrangler authenticated to the Cloudflare account
that owns the zone:

```powershell
pnpm dlx wrangler deploy --config web/yappie/wrangler.jsonc --dry-run
pnpm dlx wrangler deploy --config web/yappie/wrangler.jsonc
```

The email routes accept an encoded `ConfirmationURL` from the email after an
explicit click and preserve the installed APK's PKCE handoff. Don't add analytics
to the email routes or log their request bodies, email fragments, upstream URLs,
or redirect codes. Preserve the current Supabase mobile callback allowlist.

The Supabase email HTML is generated by `node scripts/render-auth-emails.cjs`.
Deploy the Worker and confirm its HTTPS endpoints before saving changes to the
live templates. For rollout and rollback details, see
[the auth email setup record](../../docs/AUTH_EMAIL_SETUP.md).

## Web chat beta

Guest chat uses a dedicated Cloudflare Durable Object. Production has
`WEB_CHAT_ENABLED` set to `true`. With the guest and moderator secrets configured,
the homepage shows **Start chat**. Set the flag to `false` to close guest chat
and return the homepage to prelaunch copy.

- Set `WEB_CHAT_SECRET` and `WEB_CHAT_MODERATOR_TOKEN` as distinct Worker secrets
  with at least 32 random characters each. The first signs temporary guest cookies.
  Keep the moderator token available only to the operator reviewing reports.
- For voice, set `WEB_CHAT_TURN_KEY` and `WEB_CHAT_TURN_TOKEN` from Cloudflare
  Realtime TURN. With both set, the service issues separate, short-lived relay
  credentials to each guest after they agree to a call. The Android audio gateway
  is independent.
- During validation, enable chat in a staging deployment and use two browser
  profiles or devices. Check join, cancel, optional interests, sending and retry,
  Esc to leave, rematch, report and block, tab close, and mic teardown. Include
  mobile Safari and Android Chrome at narrow widths and with the keyboard open.
- Use `GET /chat-api/moderation` with the moderator bearer token to review recent
  reports and aggregate beta counters. `POST` to the same endpoint with JSON
  containing a report `id` and an `action` of `review` or `ban`. `ban` marks the
  report reviewed and limits the reported network for seven days. Review reports
  in a private environment because the response can contain conversation excerpts.
- Before promoting the public beta, set up Cloudflare bot challenges for
  suspicious traffic and arrange operator coverage for reports. Use the queue
  join, wait bucket, abandonment, two-way chat, and voice counters to decide when
  to expand. Once the working homepage is live, submit `/sitemap.xml` in Google
  Search Console. Add the Android link after the public app release.
